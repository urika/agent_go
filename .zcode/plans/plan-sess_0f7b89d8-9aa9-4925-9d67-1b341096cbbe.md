## 为 Code Review 添加 AST 缩进规则检测

### 目标
在代码 review 过程中自动发现"for 循环体太小，后续代码意外在循环外"的模式——即本次内存泄露的根因类型。

### 方案

**创建 `agent_go/lint.py`** — 零依赖的 AST 静态检查器（仅使用 stdlib `ast`）。

**检测规则：`_check_suspicious_for_loops()`**

1. 遍历所有 `ast.For` 节点
2. 如果 for 循环体 ≤ 2 条语句 → 标记为 suspicious
3. 收集循环体内赋值的变量名（如 `st = futures[fut]`）
4. 检查 for 循环之后的兄弟语句（最多 3 条），是否使用了循环体变量
5. 如果使用 → 报告 warning（"可能的缩进错误，代码可能意外在循环外"）

**示例：** 我们的 bug 代码会被精确捕获：

```python
for fut in as_completed(futures):   # ← body = [Assign(st, ...)], len=1
    st = futures[fut]                # 赋值 st
# ↓ 后续语句使用 st, result, fut — 全部来自循环体
try:
    result = fut.result()            # uses fut
...
with meta_lock:                      # uses st, result
    ...
completed_ids.add(st["id"])          # uses st
```

→ 报 warning：`"For loop body has only 1 statement(s) but subsequent code uses loop variable(s): st, result"`

**创建 `tests/test_lint.py`** — 针对所有 `agent_go/*.py` 运行检查，有 warning 则 pytest 失败。

**更新 `AGENTS.md`** — 在 Key Design Decisions 中增加一条 AI review checklist，提醒 agent 在 review 双分支调度逻辑时检查缩进对称性。

**不依赖外部工具** — 不需要 ruff 插件、不需要第三方包。使用 `pytest tests/test_lint.py` 作为 CI check 的一部分。

### 不做的
- ❌ 不创建 ruff 自定义插件（需要单独包，维护成本高）
- ❌ 不改动现有 CI（`pytest tests/` 已包含新测试）
- ❌ 不做 100% 精确的语义分析（启发式，宁可误报也不漏报）
