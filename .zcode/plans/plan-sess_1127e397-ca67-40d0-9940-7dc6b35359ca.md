# 解耦方案：核心流程与评估/分级/测试验证功能隔离

## 核心判断

用户指出"分析决策和测试验证功能应与核心功能解耦"——调查证实这是对的，且**真正的耦合远比想象中轻**：

- **只有 2 处静态强绑**：`executor.py:12`（evaluator）+ `pipeline.py:10`（notify）的顶部 import
- **其余 6 个增强已是动态 import**（goal/agent_loop/router/skills/notify-subtask）：模式成熟可复制
- **S8 评估机制是新增的"最重增强"**：bench 编排器会反向调用 `run_subtask`，若直接 import 会引入最严重的反向耦合

## 方案选型：动态 import + 容错隔离 + 子进程隔离（不引入框架）

**不选事件总线/插件包的理由**：PRD line 311 明确把"协调机制过度设计"列为风险；仓库已有 6 个成功的动态 import 先例；当前规模不值得框架级抽象。

### 解耦四原则（写入文档作为后续守则）

1. **核心模块（pipeline/executor/subtask/cli-run）不静态 import 增强模块**——所有增强用函数内动态 import
2. **每个增强调用点必须有 try/except 容错**——增强失败绝不中断核心流程（已有 4 个增强做到了：evaluator/notify/metering/agent_loop，其余补齐）
3. **增强模块单向依赖核心**——核心不 import 增强；增强（如 bench）需要核心能力时，用 CLI subprocess 隔离，不做 Python import
4. **增强功能开关统一**——每个增强都有 `enabled` flag（默认 False），关闭时不 import、不调用、不写文件

## 第二部分：S8 评估机制的隔离架构（设计核心）

### 2.1 子进程隔离（最彻底的解耦）

**bench 编排器不 import 核心模块**，而是通过 subprocess 调用 `agent_go run`：

```
agent_go/bench.py（编排器，纯新增，不 import pipeline/executor）
  │
  ├─ 不 import 核心；用 subprocess 调 CLI
  │
  for model in [--models]:
    for task in eval_suite/:
      写临时 config.json（worker_models.medium = model）
      subprocess.run(["python", "agent_go.py", "run", task.repo, task.task,
                      "--yes", "--headless",
                      "--config", tmp_config_path])
      读 task_dir/metering.jsonl + meta.json → 解析 pass_rate/cost/latency
      写一行 results.jsonl
```

**为什么子进程优于 import**：
- **进程级隔离**：被测模型崩溃/超时不影响编排器
- **天然并发隔离**：可并行跑多模型（subprocess 各自独立进程空间）
- **无反向耦合**：编排器只依赖 `metering.jsonl`/`meta.json` 的数据契约（已是稳定格式），不依赖核心代码
- **复用已有 CLI**：`cmd_run` 已支持 `--yes`/`--headless`/config 注入，无需为核心改任何代码

### 2.2 数据契约固化（编排器与核心的唯一接口）

bench 与核心的耦合面收敛为**两个文件的数据格式**（已存在、稳定）：

```yaml
# 契约 1：metering.jsonl（核心写，bench/eval 读）
每行一个 JSON 事件，必需字段：
  role, actual_provider, actual_model, difficulty,
  prompt_tokens, completion_tokens, cost_usd, latency_ms,
  result, fallback_reason, task_id, subtask_id

# 契约 2：meta.json（核心写，bench/eval 读）
results 数组，每个元素必需字段：
  subtask_id, status, verify_ok, retry_count,
  timing.claude_execute_ms, difficulty
```

把这两个契约写入 `docs/spec.md` 的"数据格式"段，作为核心↔评估的稳定接口。核心改动不得破坏这两个格式（向后兼容约束）。
