### 1. P0: 全链路 E2E 测试 — 新增 `tests/test_e2e_full_workflow.py`

**目标**：模拟 Plan → Decompose → Execute → PR 的完整流程，验证跨模块编排正确性。

**方案**：不调用真实的 `cmd_run`（过于复杂），而是按 `cmd_run` 相同的步骤顺序直接调用各函数，但在外部依赖边界 mock：


### 2. P1: Phase 3 Review 测试 — 新增 `tests/test_review.py`

**目标**：测试审查命令的格式化输出、三态审批写入。

**方案**：构造带 meta.json 的伪 task 目录，直接测试 `_show_task_review` 函数和 `cmd_review`。

```python
class TestCmdReview:

            "results": results,
```

### 3. P1: 验证循环 E2E 测试 — 扩展到 `tests/test_executor.py`

**目标**：测试 `_verify_changes` 的 retry→fix→reverify 完整循环。

**方案**：直接测试 `_verify_changes` 函数（executor.py 的内部函数），mock 其依赖的 `subprocess.run`（验证命令）和 `_run_headless`（修复）。

```python
class TestVerificationLoopE2E:
    def test_verify_fail_then_fix_then_pass(self, temp_repo, task_dir, logger):
        """验证失败 → 修复 → 重新验证通过"""
        worktree = temp_repo
        # 首次验证失败，第二次验证通过
        call_count = [0]
        def mock_subprocess_run(cmd, **kw):
            call_count[0] += 1
            if "status" in str(cmd):
                return MagicMock(returncode=0, stdout=" M main.py\n")
            if "diff" in str(cmd):
                return MagicMock(returncode=0, stdout="1 file changed, 10 insertions(+)")
            if "pytest" in str(cmd):  # 验证命令
                rc = 1 if call_count[0] == 1 else 0  # 首次失败，后续通过
                return MagicMock(returncode=rc, stdout="", stderr="")
            return MagicMock(returncode=0, stdout="", stderr="")
        
        with patch("subprocess.run", side_effect=mock_subprocess_run), \
             patch("agent_go.executor._run_headless") as mock_fix:
            mock_fix.return_value = MagicMock(returncode=0)
            
            result = _verify_changes("task-1", "sub-1", basic_subtask, worktree, 
                                      True, "TASK.md", {}, "tag", set(), Lock(), logger)
        
        assert result["verify_ok"] is True
        assert result["retry_count"] == 1  # 修复了 1 次
        mock_fix.assert_called_once()  # 修复 prompt 被调用
    
    def test_max_retries_then_fail(self, temp_repo, task_dir, logger):
        """验证始终失败 → 达到 max_retries → verify_ok=False"""
        with patch("subprocess.run") as mock_run, \
             patch("agent_go.executor._run_headless") as mock_fix:
            mock_run.side_effect = subprocess_side_effect_always_fail
            mock_fix.return_value = MagicMock(returncode=0)
            
            result = _verify_changes(..., max_retries=2, ...)
        
        assert result["verify_ok"] is False
        assert result["retry_count"] == 2  # max_retries=2
```

**测试用例（3 个）**：
| 测试 | 场景 | 关键断言 |
|------|------|---------|
| `test_verify_fail_then_fix_then_pass` | 首次验证失败 → 修复 → 通过 | retry_count=1, verify_ok=True |
| `test_max_retries_then_fail` | 始终失败 → 达到上限 → blocked | retry_count=max, verify_ok=False |
| `test_semantic_eval_triggers_repair` | shell 通过但语义评估未通过 → 修复 | 语义失败触发 _run_headless |

### 4. P2: 并发安全压力测试 — 扩展到 `tests/test_pipeline.py`

**目标**：验证高并发下管线不崩溃、metering 不丢失。

**方案**：复用 `test_pipeline.py` 的 5 路 mock 模式，将子任务数增至 20，parallel=10。

```python
class TestPipelineConcurrencyStress:
    def test_high_concurrency_no_crash(self, temp_dir, logger):
        """20 子任务 parallel=10 不崩溃"""
        confirmed = [_make_subtask(f"sub-{i}") for i in range(20)]
        repo, task_dir = _setup_repo_and_task_dir(temp_dir, "t-stress")
        
        with patch("agent_go.pipeline.run_subtask") as mock_run, \
             patch("agent_go.pipeline._set_gc_auto", ...), \
             patch("agent_go.pipeline._worktree_remove", ...), \
             patch("agent_go.pipeline._worktree_prune", ...), \
             patch("agent_go.pipeline.subprocess.run", ...):
            mock_run.side_effect = [_success_result(f"sub-{i}") for i in range(20)]
            
            meta = _default_meta("t-stress")
            _run_pipeline(confirmed, repo, task_dir, logger, ...)
        
        assert meta["status"] == "completed"
        assert len(meta["results"]) == 20
    
    def test_concurrent_metering_intact(self, temp_dir, logger):
        """并发场景 metering.jsonl 完整无损"""
        # 同上的 setup + 额外验证 metering.jsonl
        metering_path = task_dir / "metering.jsonl"  # _run_pipeline 会从 config._metering_path 读取
        assert metering_path.exists()
        lines = metering_path.read_text().strip().split("\n")
        assert len(lines) == 20  # 每个子任务一条 metering
```

**测试用例（2 个）**：高并发不崩溃 / metering 完整
