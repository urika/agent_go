## 0. 设计目标

把 agent_go 从"批处理调度器"升级为**"结构化协作平台"**，在终端约束下实现：

1. **执行可见** — 用户在等待期始终知道"它还在动、在做什么、还要多久"。
2. **干预低摩擦** — 关键决策点（Plan 确认、验证失败）能介入，但默认路径零摩擦。
3. **状态可恢复** — 任意时刻中断都能无损续跑，不丢上下文。
4. **输出可消费** — 同一份逻辑输出，能在终端 / CI / IDE 三种场景被正确消费。

非目标（本期不做）：
- Web GUI（与 Devin 对标属于另一条产品线）
- 完整的国际化框架（仅做中/英可切换预留）
- 鼠标驱动的全图形化 TUI（保留键盘为主交互）

## 1. 设计原则

| 原则 | 含义 | 在 agent_go 的体现 |
|---|---|---|
| **渐进式披露** | 默认最少信息，需要时展开 | Plan 默认显示 id+标题+依赖，详情需展开 |
| **冷静的 UI** | 不刷屏，但不静默 | 进度行用 `\r` 覆盖而非追加 |
| **可逆性** | 任何操作都能撤销/回滚 | Plan 编辑可 diff、worktree 可 inspect/replay |
| **状态常驻** | 关键状态始终在视线内 | TUI 顶部状态条 + 底部进度条 |
| **双模式同源** | 交互/无人值守共用同一逻辑 | `--yes` 跳过的是"问询"，不是"功能" |
| **语义优先** | 用方法语义而非视觉修饰区分输出 | `console.success()` 而非 `print("✅")` |

## 2. 用户角色与场景

### 2.1 角色

| 角色 | 特征 | 核心诉求 |
|---|---|---|
| **首次用户 (A)** | 第一次跑，没读 README | 一个命令看到结果，不被 6 个选项吓退 |
| **熟练用户 (B)** | 经常用，懂 wave/worktree | 高效编辑 Plan、实时监控、快速排错 |
| **CI/Headless 用户 (C)** | 脚本/管道调用 | 纯 JSON 输出、稳定退出码、无交互 |
| **审查者 (D)** | 任务跑完后看结果 | 快速定位失败、查看 diff、决定 approve |

### 2.2 核心场景与用户旅程

#### 场景 S1：首次用户完成一个简单任务（A）

```
认知  → 输入命令 → 看到加载 → Plan 简短展示 → 一键确认
       → 进度条 → 结果摘要 → 完成
```

**当前痛点**：6 选项确认菜单 + 80 行 Plan 输出 + 静默等待。

**目标体验**：
- Plan 紧凑展示（步骤列表 + 预计耗时一行）
- 默认 Enter 直接确认，不弹菜单
- 等待期有动态进度行
- 结束有 3-5 行摘要

#### 场景 S2：熟练用户并发执行复杂任务（B）

```
规划 → 多次迭代 Plan → $EDITOR 精修 → --parallel 3 并发
     → TUI 仪表盘实时监控 → 失败子任务介入 → inspect 现场
```

**当前痛点**：Plan 编辑是逐字段终端输入；执行期无 TUI；中断无摘要。

**目标体验**：
- `[E]` 触发 `$EDITOR` 打开 `PLAN.md`，保存即采纳
- `--interactive` 启动 TUI 仪表盘（默认文本模式，TUI 可选）
- SIGINT 弹出暂停摘要，告知 resume 命令

#### 场景 S3：CI 流水线无人值守（C）

```
触发 → --yes --json --parallel 3 → JSON Lines 流式输出
     → 退出码判定 → 失败时读取 JSON 定位
```

**当前痛点**：`--quiet` 不静音（ui.py 绕过 Console）；无 JSON 模式。

**目标体验**：
- `--json` 全局模式，每个事件一行 JSON
- `--yes` 下零交互、零 emoji
- 退出码：0=全成功 / 1=部分失败 / 2=配置错误

#### 场景 S4：审查者事后审查（D）

```
review --task <id> → per-file diff 摘要 → 失败子任务定位
                  → --deep 独立模型分析 → approve/reject
```

**当前体验已较完整**，本期仅做输出格式标准化。

## 4. 组件规范

### 4.1 输出语义层（Console）

#### 4.1.1 等级协议

| 方法 | 语义 | 图标 | quiet | verbose | JSON 模式 |
|---|---|---|---|---|---|
| `.error()` | 致命错误 | ❌ | 始终 | 始终 | `{"level":"error",...}` |
| `.warning()` | 可恢复告警 | ⚠️ | 始终 | 始终 | `{"level":"warning",...}` |
| `.success()` | 关键里程碑 | ✅ | 抑制 | 始终 | `{"level":"success",...}` |
| `.info()` | 纯信息 | （无） | 抑制 | 始终 | `{"level":"info",...}` |
| `.progress()` | **新增**：覆盖型进度 | ➜ | 抑制 | 始终 | `{"level":"progress",...}` |
| `.print()` | 通用降级 | 调用方自选 | 抑制 | 始终 | `{"level":"log",...}` |
| `.debug()` | 诊断 | 🔍 | 抑制 | 仅 verbose | `{"level":"debug",...}` |

**关键规则**：
- `.progress()` 使用 `\r` 覆盖当前行，不追加换行；其他方法均追加换行。
- `--json` 模式下所有输出改为 JSON Lines，图标字段省略。
- 错误/告警**不受 quiet 抑制**——CI 场景必须看到失败原因。

#### 4.1.2 图标常量表

```python
ICONS = {
    "success": "✅", "error": "❌", "warning": "⚠️", "progress": "➜",
    "task": "📋", "file": "📁", "time": "⏱", "cost": "💰",
    "robot": "🤖", "branch": "🌿", "link": "🔗", "search": "🔍",
    "star": "★", "skipped": "⏭️", "running": "▶", "pending": "⏳",
    "blocked": "🚫", "retried": "🔄",
}
```

**约束**：新增图标需 IDS 评审。`ICONS` 字典是唯一的图标来源，禁止字面量散落。

#### 4.1.3 颜色协议（ANSI）

> 当前完全无颜色，仅靠 emoji。新增颜色用于状态语义，非装饰。

| 语义 | ANSI | 用于 |
|---|---|---|
| `ERROR` | 红 (31) | 失败状态、致命错误 |
| `SUCCESS` | 绿 (32) | 完成状态、通过验证 |
| `WARNING` | 黄 (33) | 重试、降级、阻断 |
| `INFO` | 青 (36) | 进度、当前运行 |
| `MUTED` | 灰 (90) | 次要信息、时间戳 |
| `ACCENT` | 蓝 (34) | 当前选中项、链接 |

**降级**：检测 `NO_COLOR` 环境变量或 `term` 不支持颜色时，自动降级为纯文本（图标保留）。

#### 4.1.4 Console 绑定统一

**强制**：所有模块使用 `console = _LazyConsole()`，禁止 `get_default_console()` 直接赋值。
理由：`set_default_console()` 在 `cmd_run` 中替换实例，Lazy 代理保证延迟生效。

### 4.2 Plan 交互（Plan as File）

#### 4.2.1 状态机

```
                    ┌─────────────┐
                    │  Plan 生成中 │
                    └──────┬──────┘
                           │ 完成
                           ▼
               ┌───────────────────────┐
        ┌──────│   Plan 展示（紧凑）   │──────┐
        │      └───────────────────────┘      │
        │ Enter                               │ [E]
        ▼                                     ▼
  ┌──────────┐                       ┌────────────────┐
  │  确认执行 │ ◀────── 保存 ────────│ $EDITOR 编辑   │
  └──────────┘      (hash 变更)      │  PLAN.md       │
        │                             └────────────────┘
        │                                     │ 无变更/退出码≠0
        │                                     ▼
        │                             ┌────────────────┐
        │                             │ 提示未保存，    │
        │                             │ 返回展示        │
        │                             └────────────────┘
        ▼
   拆解子任务
```

#### 4.2.2 紧凑展示格式（默认）

替代当前 80+ 行的全量输出。默认只展示骨架：

```
┌─ 📋 执行方案 ────────────────────────────────────────┐
│ 概述: 重构认证模块，从 JWT 迁移到 OAuth2              │
│ 步骤: 4 个  ·  耗时: ~12-18 分钟  ·  并发: 3         │
├──────────────────────────────────────────────────────┤
│ [1] 迁移数据模型           → 验证: pytest            │
│       └─ 无依赖                                       │
│ [2] 修改路由配置           → 验证: pytest            │
│       └─ 依赖 [1]                                      │
│ [3] 更新中间件             → 验证: mypy              │
│       └─ 依赖 [1]                                      │
│ [4] 补充测试用例           → 验证: pytest --cov      │
│       └─ 依赖 [2][3]                                   │
├──────────────────────────────────────────────────────┤
│ [Enter] 确认   [E] 编辑   [D] 详情   [R] 重生成   [N] 取消 │
└──────────────────────────────────────────────────────┘
```

**`[D]` 详情**：展开当前选中步骤的完整信息（描述/文件/风险/Agent Prompt），进入分页浏览模式（`j/k` 翻步，`q` 返回）。

#### 4.2.3 `$EDITOR` 编辑流

**触发**：用户在确认菜单按 `E`。

```
┌──────────────────────────────────────────────────────┐
│ 📝 已在编辑器中打开 Plan                              │
│    路径: ~/.agent_go/task-xxx/PLAN.md                │
│                                                      │
│    保存后回到此处，按 Enter 采纳变更                  │
│    直接按 Enter 表示未修改，取消编辑                  │
└──────────────────────────────────────────────────────┘
（启动 $VISUAL 或 $EDITOR 或 fallback: nano）

> _   （等待 Enter）
```

**变更检测**：
1. 编辑前记录 `file_hash_before = sha256(PLAN.md)`
2. 编辑器返回后 `file_hash_after = sha256(PLAN.md)`
3. 相等 → 提示"未检测到修改"，返回展示
4. 不等 → 解析 PLAN.md，校验格式

**格式校验失败处理**：
```
⚠️ Plan 文件格式有误，无法解析：

  第 23 行: 缺少 "### [id] 标题" 格式的步骤头
  第 31 行: 依赖 [5] 不存在（有效 ID: 1-4）

[E] 重新编辑   [R] 放弃修改，使用原方案   [Q] 退出
```

#### 4.2.4 PLAN.md 格式约定

```markdown
# 执行方案

## 概述
<任务概述>

## 预估工作量
<文本>

## 步骤

### [1] 步骤标题
- description: <多行描述>
- files: path/a.py, path/b.py
- verification: `pytest tests/`
- depends_on: (无 / 1,2)
- difficulty: easy|medium|hard
- agent: developer|architect|reviewer|tester
- skill: skill-a, skill-b
- Risks:
  - 风险点 1
  - 风险点 2

### [2] ...

## 依赖关系
（可选，自动从步骤推导）
```

**解析规则**：
- `### [N]` 行的正则：`^###\s*\[(\d+)\]\s*(.+)$`
- 字段以 `- key: ` 前缀形式，`key` 在白名单内（`description` / `files` / `verification` / `depends_on` / `difficulty` / `agent` / `skill` / `Risks`）
- 多值字段（files/skill/depends_on/Risks）支持逗号分隔 YAML 行列表
- 未知 key 忽略（向前兼容）
- **文案语种**：key 统一英文，自由文本值可用中文或英文——解析器只识别 key 名，不依赖值语种

### 4.3 执行透明度

#### 4.3.1 单行动态进度行

**触发**：每个 subtask 开始执行（claude 进程启动后）。

**格式**：
```
➜ sub-2: 修改路由配置  [45s]  验证: ⏳  重试: 1/3
```

**刷新策略**：
- 每 5 秒用 `\r` 覆盖
- 耗时 (`[45s]`) 实时更新
- 状态字段（验证/重试）在状态变更时立即更新（不等 5s）
- claude 进程结束后，**提交该行**（追加换行），变为永久记录

**多并发场景**（`--parallel > 1`）：
- 同时显示 N 个进度行（N ≤ 并发数）：
```
➜ sub-1: 迁移数据模型  [12s]  验证: ✓
➜ sub-2: 修改路由配置  [45s]  验证: ⏳  重试: 1/3
➜ sub-3: 更新中间件    [08s]  验证: ⏳
```
- 每行独立 `\r` 覆盖（使用 ANSI 光标控制：`\033[<N>A` 上移 N 行）
- 超过终端可见行数时，只显示最新的 N 个

**降级**：
- `--quiet` / `--json`：不输出进度行
- 非 TTY（管道/重定向）：不输出（检测 `sys.stdout.isatty()`）

**并行 stdout 争用约束**（设计总监评审 B3）：在 `--parallel > 1` 模式下，多个 worker 线程（`run_subtask` 经 `ThreadPoolExecutor`）同时往同一 stdout 输出。进度行的 `\r` + `\033[<N>A` 光标控制依赖**独占 stdout**。实践中不可靠——任何 worker 的 `console.print()` 叠在该行上即导致花屏。

约束：
- `--parallel > 1` 且 `isatty()` = true 时，进度行应**降级为单行**（仅显示最近变更子任务），或启用输出仲裁——所有 `console.*` 输出经单一渲染队列（生产者-消费者线程），面板渲染器拥有 stdout 独占权。
- 默认实施方式：并行时降级为单行，不做队列（成本低、无延迟风险）。TUI 模式（`--interactive`）拥有完整面板，无此争用。

#### 4.3.2 验证失败上下文展示

**触发**：subtask 验证失败，进入重试决策前。

**当前**（单行）：
```
✅ 1/3 完成
📊 验证失败
[C]继续 [R]重试 [M]修改 [A]中止
```

**目标**（结构化卡片）：

```
┌─ ❌ sub-2 验证失败 ──────────────────────────────────┐
│ 重试: 1/3   耗时: 45s   变更: +23/-5                │
├──────────────────────────────────────────────────────┤
│ 📋 验证命令                                          │
│   pytest tests/test_routes.py                       │
│                                                      │
│ ⚠️ 失败输出（尾部 8 行，完整见 verification.log）    │
│   FAILED tests/test_routes.py::test_login           │
│     AssertionError: expected 200, got 401           │
│   FAILED tests/test_routes.py::test_logout          │
│     KeyError: 'token' in response                   │
│   ===== 2 failed in 3.21s =====                     │
│                                                      │
│ 📁 文件变更                                          │
│   src/routes.py   +15/-3                            │
│   src/auth.py     +2/-1                             │
├──────────────────────────────────────────────────────┤
│ [R] 重试（注入失败上下文）  [C] 跳过  [M] 手改  [A] 中止 │
│ （--yes 模式下自动 R，5 秒后执行）                    │
└──────────────────────────────────────────────────────┘
```

**字段来源**：
- 重试次数：`executor.py` 验证循环计数器
- 验证命令：subtask 的 `verification` 字段
- 失败输出：`subprocess` 的 stderr 尾部 N 行（N = `min(8, terminal_height/3)`）
- 文件变更：`git diff --stat` 在 worktree 上执行

**截断规则**：
- 失败输出 > 8 行：显示尾部 8 行 + 提示完整路径
- 变更文件 > 5 个：显示前 5 + `... 共 N 个文件`

**自动重试倒计时**（`--yes` 模式）：
```
[R] 自动重试中... 5  （按 Ctrl+C 中止）
```
倒计时期间允许 Ctrl+C 切换到手动模式。

#### 4.3.3 中断（SIGINT）UX

**当前**：静默 `sys.exit(0)`，用户不知道发生了什么。

**目标**：
```
┌─ ⏹ 任务已暂停 ──────────────────────────────────────┐
│ task-20260726-143021-ab3                             │
│                                                      │
│ 进度: 2/4 子任务完成                                 │
│   ✅ sub-1  迁移数据模型                              │
│   ✅ sub-2  修改路由配置                              │
│   ⏸ sub-3  更新中间件        （已暂停）              │
│   ⏳ sub-4  补充测试用例      （未开始）              │
│                                                      │
│ 💾 状态已保存。恢复命令:                             │
│    agent_go resume task-20260726-143021-ab3          │
└──────────────────────────────────────────────────────┘
```

**实现**：
1. 信号处理器设置 `_interrupted` 标志（已有）
2. Pipeline 在 wave 边界检测标志后，**先打印摘要再退出**
3. TUI 模式下：弹出模态确认 `[R]恢复 [Q]退出 [S]保存退出`

### 4.4 可选 TUI 仪表盘（--interactive）

#### 4.4.1 布局规范

```
┌─ agent_go  task-20260726-143021-ab3  [Wave 2/3]  1m30s  $0.04 ───┐
│                                                                   │
```

**区域划分**（按终端宽度自适应）：

| 区域 | 宽度 | 高度 | 内容 |
|---|---|---|---|
| 顶部状态条 | 100% | 1 行 | task_id + wave 进度 + 耗时 + 累计成本 |
| 任务列表（左） | 40% | 剩余 - 2 | 子任务状态树 |
| 详情面板（右上） | 60% | 40% | 选中 subtask 的元数据 |
| 日志面板（右下） | 60% | 60% | 选中 subtask 的实时日志尾部 |
| 底部帮助条 | 100% | 1 行 | 快捷键提示 |

**窄终端降级**（< 100 列）：
- 详情/日志面板隐藏，按 `Enter` 全屏展开
- 任务列表占满宽度

**极小终端**（< 50 列 或 < 8 行）：
- 退化为单行状态：`sub-2 运行中 [45s] 重试 1/3`
- 提示 `终端过小，建议 ≥ 100x30`

#### 4.4.2 任务列表项规范

每个 subtask 占 1-2 行：

```
<图标> <id>  <标题截断>  <耗时>
  └ <状态附注>          （仅非正常状态显示）
```

**图标语义**：
| 状态 | 图标 | 颜色 |
|---|---|---|
| 完成 | ✅ | 绿 |
| 无变更 | ⏭️ | 灰 |
| 降级完成 | ⚠️ | 黄 |
| 运行中 | ▶ | 青（闪烁） |
| 等待依赖 | ⏳ | 灰 |
| 验证失败重试中 | 🔄 | 黄 |
| 失败 | ❌ | 红 |
| 阻断 | 🚫 | 红 |
| 暂停 | ⏸ | 黄 |

**状态附注示例**：
- `等待 sub-1,sub-2`
- `验证失败，重试中 (1/3)`
- `上游失败，已阻断`
- `降级完成（worktree clone 失败）`

#### 4.4.3 详情面板字段

```
<标题>
状态: <status>          重试: <n>/<max>
验证: <level> (<result>)
变更: <file> <+/->
      <file> <+/->
Agent: <type>           Skill: <skills>
难度: <difficulty>      模型: <model>
失败原因: <reason>      （仅失败时）
```

**字段缺失处理**：缺失字段不显示该行（不留空行）。

#### 4.4.4 日志面板

**内容源**：
- `execution.log` 的尾部（logger 输出）— 当前已有
- **新增**：claude stdout/stderr 尾部（需 subtask.py 写入 `output.log`）
- **新增**：验证命令输出尾部

**刷新**：500ms 轮询，diff 增量追加（不全量重绘）。

**滚动**：
- 默认跟随尾部（`tail -f` 行为）
- 按 `l` 进入浏览模式：`j/k` 翻行，`g/G` 跳首尾，`/` 搜索，`q` 返回跟随

#### 4.4.5 快捷键映射

| 键 | 功能 | 模式 |
|---|---|---|
| `j` / `↓` | 选择下一个 subtask | 列表 |
| `k` / `↑` | 选择上一个 subtask | 列表 |
| `Enter` | 展开/折叠 subtask 子项 | 列表 |
| `l` | 进入日志浏览模式 | 详情 |
| `d` | 显示该 subtask 的 git diff | 详情 |
| `r` | 强制刷新 | 全局 |
| `1-4` | 过滤：全部/运行/完成/失败 | 列表 |
| `Tab` | 切换焦点：列表 ↔ 详情 | 全局 |
| `?` | 帮助 overlay | 全局 |
| `q` | 退出 TUI（任务继续后台） | 全局 |

**退出 TUI 的语义**：
- TUI 退出 ≠ 任务中止
- 任务转入后台继续执行（日志写文件）
- 提示：`任务继续后台运行，agent_go status --watch 重新查看`

#### 4.4.6 并发执行的可视化

`--parallel 3` 时同时有 3 个 subtask 运行：

- 任务列表中 3 个 `▶` 同时显示，各自独立计时
- 详情面板**默认跟随最近状态变更的 subtask**（用户未手动选择时）
- 手动选择（`j/k`）后锁定，直到用户再按 `Tab` 回到自动跟随
- 日志面板顶部标注当前来源：`日志: sub-2（自动跟随）` 或 `日志: sub-3（手动锁定）`

### 4.5 最终报告

#### 4.5.1 三种输出模式

**终端模式（默认）**：
```
═══════════════════════════════════════════════════════
  📦 最终报告  task-20260726-143021-ab3
  耗时: 4m32s   成本: $0.12   $/pass: $0.04
═══════════════════════════════════════════════════════
  ✅ sub-1  迁移数据模型      12s   +8/-2     验证: ✓
  ✅ sub-2  修改路由配置      45s   +23/-5    验证: ✓  (重试 1)
  ⏭️ sub-3  更新中间件        0s    无变更
  ❌ sub-4  补充测试用例      ----  阻断      (依赖 sub-2 失败级联)

  ⚠️ 1 个子任务失败，2 个 worktree 已保留供审查:
     ~/.agent_go/task-.../sub-4/work
     agent_go inspect task-... 查看
═══════════════════════════════════════════════════════
```

**紧凑模式（`--quiet`）**：
```
sub-1: ✅ 12s +8/-2
sub-2: ✅ 45s +23/-5 retry=1
sub-3: ⏭️ no_changes
sub-4: ❌ blocked_by=sub-2
RESULT: partial_failure (3/4 ok) cost=$0.12
```

**JSON 模式（`--json`）**：
```json
{"event":"task_complete","task_id":"task-...","status":"partial_failure","duration_sec":272,"cost_usd":0.12,"dollar_per_pass":0.04,"results":[{"id":"sub-1","status":"completed","duration_sec":12,"insertions":8,"deletions":2,"verify_ok":true},...]}
```

#### 4.5.2 保留 worktree 提示

失败/blocked 子任务的 worktree 保留时，报告末尾必须有可操作的提示：

```
🔍 保留现场 (1 个):
   ~/.agent_go/task-.../sub-4/work
   git branch: agent_go/task-.../sub-4
   原因: 上游 sub-2 失败级联阻断

   排查命令:
     cd ~/.agent_go/task-.../sub-4/work
     git log --oneline -5
     agent_go inspect task-...
```

### 4.6 JSON 全局模式（`--json`）

#### 4.6.1 事件 schema

所有输出转为 JSON Lines，每行一个事件：

```json
{"event": "<type>", "ts": "<ISO8601>", "level": "<info|warning|error|success>", "data": {...}}
```

**事件类型清单**：

| event | 触发时机 | data 关键字段 |
|---|---|---|
| `task_start` | cmd_run 开始 | task_id, task, repo |
| `plan_generated` | Plan 生成完成 | steps, duration_sec, cached |
| `plan_confirmed` | 用户确认 | iteration, edited |
| `subtask_start` | subtask 开始 | id, title, depends_on |
| `subtask_progress` | 进度更新（5s） | id, elapsed_sec |
| `subtask_verify` | 验证结果 | id, ok, level, retry |
| `subtask_complete` | subtask 结束 | id, status, duration_sec, changes |
| `subtask_failed` | subtask 最终失败 | id, reason, retry_count |
| `task_paused` | SIGINT 暂停 | completed, remaining |
| `task_complete` | 任务结束 | status, cost_usd, results |

**退出码**：
- `0`：全部成功（含 no_changes/degraded）
- `1`：部分失败
- `2`：配置错误 / 任务无法启动

## 6. 边界情况与错误状态

### 6.1 非交互环境检测

| 检测条件 | 行为 |
|---|---|
| `sys.stdin.isatty() == False` | 自动启用 `--yes` 模式，警告一次 |
| `sys.stdout.isatty() == False` | 禁用 TUI 和进度行，禁用颜色 |
| `NO_COLOR` 环境变量存在 | 禁用颜色（保留图标） |
| `AGENT_GO_INTERACTIVE=1` | 强制交互（即使 `--yes`） |

### 6.2 终端尺寸

| 尺寸 | 行为 |
|---|---|
| ≥ 100 列 × 30 行 | 完整 TUI 布局 |
| 80-99 列 | 紧凑 TUI（详情/日志面板减宽） |
| 50-79 列 | 单列 TUI（列表全宽，详情按 Enter 展开） |
| < 50 列 或 < 8 行 | 退化为单行状态 + 提示 |

**resize 处理**：
- 捕获 `curses.KEY_RESIZE`
- 调用 `curses.resizeterm` + 重绘
- 禁止 `_safe_addstr` 静默吞异常（改为 debug 日志 + 跳过该帧）

### 6.3 Plan 编辑的异常路径

| 情况 | 处理 |
|---|---|
| `$EDITOR` 未设置 | fallback: `nano` → `vi` → 报错 |
| 编辑器退出码 ≠ 0 | 视为取消，提示"编辑器异常退出" |
| 文件未修改（hash 相同） | 提示"未检测到修改"，返回展示 |
| 格式校验失败 | 显示错误行号 + 重新编辑/放弃 选项 |
| 步骤 ID 不连续 | 允许（如 1,2,4），依赖按 ID 引用 |
| 依赖形成环 | 报错："检测到依赖环: 1→2→3→1"，拒绝 |
| 删除了被依赖的步骤 | 报错："[2] 依赖已删除的 [1]"，拒绝 |
| 所有步骤被删 | 报错："至少需要一个步骤"，拒绝 |

### 6.4 中断时机的细化

| 时机 | 行为 |
|---|---|
| Plan 生成中（API 调用） | 取消请求，退出 |
| Plan 确认菜单 | 直接退出，不保存 |
| 子任务执行中（claude 运行） | SIGTERM → claude → 保存 checkpoint → 暂停摘要 |
| 验证失败卡片倒计时 | 取消倒计时，立即进入手动模式 |
| TUI 浏览日志 | 不退出，仅取消浏览模式 |
| 最终报告输出 | 忽略（快结束了） |

### 6.5 并发执行的竞态展示

| 情况 | TUI 行为 |
|---|---|
| 3 个 subtask 同时完成 | 按完成顺序逐个更新，500ms 内合并刷新 |
| 1 个失败触发级联阻断 | 阻断的 subtask 立即标红，详情面板切到失败项 |
| 用户手动锁定详情在 sub-A，sub-B 失败 | 顶部状态条闪烁提示"sub-B 失败，按 b 查看" |
| worktree 创建失败（降级 clone） | 详情面板标注"降级模式"，不影响进度 |

## 7. 可访问性

### 7.1 颜色不依赖

- 所有状态信息**必须同时有图标 + 文字**，不能仅靠颜色区分
- 示例：`❌ 失败`（图标+文字）而非仅红色文字

### 7.2 无 emoji 降级

`--no-emoji` 标志（或检测 `LANG` 不含 UTF-8）：

| 图标 | 文本降级 |
|---|---|
| ✅ | `[OK]` |
| ❌ | `[FAIL]` |
| ⚠️ | `[WARN]` |
| ▶ | `[RUN]` |
| ⏳ | `[WAIT]` |
| ⏭️ | `[SKIP]` |

### 7.3 键盘可达性

- TUI 所有操作必须键盘完成（鼠标为增强，非必需）
- 快捷键不依赖 Shift 之外的修饰键（保证各种终端可用）
- 帮助 overlay (`?`) 列出全部快捷键

### 7.4 屏幕阅读器友好

- `--json` 模式输出纯结构化数据，便于辅助技术消费
- 避免 ASCII art 在非 TTY 输出（`isatty` 检测）
